## 2. 右侧菜单与输入区

右侧菜单采用“入口列表 → 独立面板/弹窗”，避免把所有设置一次摊开。每个面板有明确关闭或返回入口，手机键盘打开时也能操作。

| 入口 | 点开后的内容 |
| --- | --- |
| 星星 | System Prompt / 人设，进入只读弹窗 |
| 摘要 | 复用现有摘要管理弹窗 |
| 书签 | 复用现有书签管理弹窗 |
| 券包 | 打开现有券包，统一弹窗层级与关闭行为 |
| 模型 | 当前使用的渠道与模型、切换模型、API 管理 |
| 设置 | 温度、思考预算、流式输出、缓存、上下文 |
| 壁纸 | 背景图、背景透明度、气泡颜色、气泡透明度、磨砂开关及强度 |
| 换窗 | 固定菜单最下端，沿用现有携带最近 50 条的逻辑 |

“模型”一行直接显示当前模型的小字标签，左下角原标签移除。摘要和书签数量可以放在各自菜单行。若保留“共多少层”，也移入菜单，输入区不再常驻统计文字。

输入区布局：`[输入文字……] [＋] [发送]`。语音使用苹果键盘听写，不添加麦克风按钮。

点击 ＋ 才展开输入框下方的功能区：上传照片、Timeline、长聊/短聊切换。记录中的 Timeline 用功能项上的状态和计时显示，折叠时最多在 ＋ 上显示一个小点。键盘和窄屏下不得横向溢出。附件预览只在实际选择附件后出现。

移除聊天页及相关面板里的说明性小字，包括“人设与参数不跟模型走”“新窗口会立即打开”、参数科普、内部存储路径等。保留字段名、当前值、必要错误提示，以及已有删除操作的简短确认。

移除上述界面所有“恢复默认”“外观全部恢复默认”和颜色恢复默认入口，不能只改名或藏进更多菜单。数据迁移所需的内部默认值仍保留。

## 3. 人设编辑与磨砂

### 人设编辑

进入“星星”后点 System Prompt 打开弹窗；正文默认只读，点击正文不进入编辑。

点击“编辑”才进入草稿模式，出现保存、取消。只有保存才更新正式人设；取消丢弃草稿。草稿有变化时，点击遮罩、返回或关闭不得静默保存或丢失，使用简短的放弃修改确认。多设备有新版本时避免旧草稿静默覆盖。

长短模式指令独立管理，不把临时模式提示写进这份用户人设。

### 磨砂

“壁纸”面板内给“我的气泡”和“星星的气泡”分别提供：颜色、透明度、磨砂开关、磨砂强度拉杆。

初始建议：强度范围 0–20 px，界面显示 0–100%；关闭磨砂后保留上次强度，重新打开恢复该值。沿用已有日/夜配色分离方式，新字段兼容旧设置；首次升级保持原有视觉效果。

透明度和磨砂强度分开控制。半透明背景才能看出底图模糊，默认颜色也必须应用透明度与磨砂，不能只对自定义颜色生效。历史、正在生成、短聊分段统一样式。用手机验证滚动流畅度。

## 4. 长聊 / 短聊

### 表达规则

| 模式 | 预期行为 |
| --- | --- |
| 长聊 | 保持现在适合亲密交流、故事和细节描写的完整表达；不强迫每轮凑够字数 |
| 短聊 | 日常聊天，每次只推进一两个意思；简单回应可以很短，少长篇动作独白、重复总结和连续追问 |

短聊仍沿用星星原有人设、关系和记忆。模型收到明确的当前模式规则；必要的问题完整回答，不为追求短而漏掉关键内容。用户请求展开时允许更长解释。

初始默认长聊；选择按会话保存、跨设备同步。换窗继承当前模式。切换从下一次发送生效，不改变正在生成的回复；每次请求、待发消息和回复版本记录当时模式。旧消息保留原有展示，不被当前开关重新拆分。重生成默认沿用该轮记录的模式。

### 分气泡方案

参考项目的隐藏分隔标记只用于兼容旧回复。正式方案不要求模型决定气泡边界：模型只接收短聊行为提示，Lumbre 使用确定性的自适应排版器生成气泡。

一轮仍保存为一个 assistant 消息/版本，正文保留完整文本，另保存带版本号的字符区间布局。UI 显示多个气泡，但摘要、上下文窗口、消息计数、费用和重生成仍把它作为一轮；导出保留完整正文。气泡数量随内容增长，没有固定上限，也不会增加模型调用次数。

排版器只处理模型正文，依次考虑自然段、句末、换行、分号、冒号、破折号、Emoji、逗号、转折词和中文词语边界。完全没有标点的长回复也必须按安全长度继续生成气泡。代码块、行内代码、链接、表格、列表、思考块、工具调用和卡片不能被破坏。流式过程中已经提交的气泡边界保持稳定，只有最后一个气泡继续增长；完成后保存同一份布局，保证刷新、同步和版本切换不重新排版。

短聊需要同时调整模式提示和适配器的输出预算；不能只换 UI，也不能直接把共享总上限压成几百 tokens，造成思考预算冲突。按实际渠道区分思考与可见输出限制；无法分别限制的渠道用模式提示控制，并验证停止原因。达到上限时不静默剪掉结尾。

第一版随生成逐段出现，不增加逐气泡请求、强制长延迟或自动连发机器人消息。用户“连发多条后再回复”的功能不属于本次长短模式。

## 6. 参考项目核对结论

参考仓库：[whisper-tg-chat](https://github.com/jessie19900915/whisper-tg-chat)。2026-09-05 通过 GitHub 连接读取默认分支文件。

- [前端](https://github.com/jessie19900915/whisper-tg-chat/blob/main/static/index.html) 使用 `<!--split-->` 渲染 AI 多气泡，实时和历史路径都有处理。
- 同文件的 `segMode` 是用户连发几条、先保存再触发回复，不能把它直接当成本需求的“星星长短模式”。
- [语音接口](https://github.com/jessie19900915/whisper-tg-chat/blob/main/main.py) 保存原文件并用 ElevenLabs 转写。
- [上下文构建](https://github.com/jessie19900915/whisper-tg-chat/blob/main/context_builder.py) 会读取外部声学 JSON 并附加音高、停顿、响度等信息；读取路径绑定原部署目录。已确认的是消费这些数据的入口，没有在本次检查中确认其分析器的完整生成和部署链路，不能照抄路径后声称语气分析已完成。
- [README](https://github.com/jessie19900915/whisper-tg-chat/blob/main/README.md) 还提到 AI 语音回复；本次需求是用户发送语音，因此不把 AI 声音合成加入首版。

实现需要重新适配当前 Next.js 项目；不搬入该项目的整套 Python 后端、数据库或默认人设。若实际复用其代码，执行时核对并保留适用的许可证声明。

技术核对资料：[录音格式探测](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static)、[获取录音波形信号](https://developer.mozilla.org/en-US/docs/Web/API/AnalyserNode/getFloatTimeDomainData)、[ElevenLabs 转写能力](https://elevenlabs.io/docs/overview/capabilities/speech-to-text)。
