- 旧会话、消息版本、摘要、阶段摘要、书签、外观和聊天参数继续沿用原数据结构；旧明文模型凭据只在内存中排队迁移，持久化副本会自动清除。
- 同步和离线待发箱迁入 `src/features/chat/sync/`；保留“先落待发箱再显示”的顺序、联网重试、相同消息 ID 去重和 PWA 恢复监听。
- 建立统一聊天前端 API 客户端；聊天、摘要、模型列表、模型凭据、工具确认和消息追加不再各自散写 `fetch`。

- 纯界面状态迁入 `useChatViewState`；流式回复显示拆成独立组件。现有颜色、布局、文字、移动端和桌面端交互没有重设计。
- 长会话仍只把当前会话最近 50 条放入同步 localStorage，其余会话只保留目录信息；完整历史继续从服务器按需每次加载 50 条。
- 旧的 `src/lib/chatStore.ts`、`src/lib/chat-outbox.ts` 和 `src/components/chat/ChatSync.tsx` 保留兼容门面，避免其他入口一次性断裂。

## 预览环境验收

1. 将脱敏预览服务 Source 改为 `codex/lumbre-04-frontend-state`，等待部署状态变为 Running；不要绑定正式卷。
2. 电脑登录后确认：旧会话目录、当前会话内容、摘要、书签、模型渠道名称和当前模型都存在。
3. 新建一条可丢弃会话，在电脑发送 `STAGE4_DESKTOP_OK`；手机打开同一预览站，确认能看到且只出现一次。
4. 手机回复 `STAGE4_MOBILE_OK`；电脑切到另一会话再切回来，确认两端能看到手机消息、没有串进别的会话、没有重复。
5. 在这条测试会话中切换一次模型并发送消息，再对回复执行一次重 Roll；确认模型名、版本切换和用量/费用显示仍正常。
6. 生成或重生成一条可丢弃摘要，确认摘要能保存并跨设备出现；书签的查看和触发保持正常。
7. 手机把 PWA 切到后台再恢复，并完整关闭后重新打开；确认仍回到最近会话，可以继续发送。
8. 断网后在测试会话发送一条 `STAGE4_OFFLINE_OK`，再恢复网络；确认最终同步且只出现一次。测试期间不要关闭或清除浏览器数据。
9. 快速打开日记、记忆、照片、纸条、待办和时间线，确认其他家庭入口正常。

## 回退

- 预览异常时，把预览 Source 切回 `main`；预览卷保留即可，不要清空浏览器数据。
- 正式部署异常时回滚到第四块合并前的 `main`。v11 迁移不会改服务器会话格式，旧代码仍可读取；浏览器还保留 `starfire-chat-migration-backup-v11` 供诊断。
- 不要以删除 localStorage、IndexedDB 或 `/persistent` 的方式处理迁移问题。
