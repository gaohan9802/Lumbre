# Lumbre 分块修复与拆分计划

> 状态：待执行
> 制定日期：2026-09-02
> 基线提交：`62948285f996207cbb33c09ec272e644157dc613`
> 总原则：一次只处理一块；完成测试、预览部署和稳定观察后，才进入下一块。

## 1. 目标和边界

Lumbre 目前已经是一个可以使用的完整应用。本计划不是重写，也不是立即拆成多个独立服务，而是先在当前 Next.js 项目中把四种职责分开：

1. 数据保存层；
2. 工具与权限层；
3. 模型调用管道；
4. 前端界面与聊天状态。

计划首先增加一个不计入四块的“安全基线”阶段。后续执行顺序固定为：

```text
阶段 0：安全基线
  ↓
第一块：数据保存层
  ↓
第二块：工具与权限层
  ↓
第三块：模型调用管道
  ↓
第四块：前端界面与聊天状态
```

任何阶段没有通过验收，都不得开始下一阶段。

## 2. 当前结构和主要风险

当前主要调用链：

```text
浏览器/PWA
    ↓
Next.js API
    ↓
模型调用与工具循环
    ↓
/persistent 数据及外部服务
```

目前前端、模型网关、工具执行和数据保存都放在同一个 Next.js 项目中。需要重点处理的现状包括：

- `src/app/api/chat/route.ts` 同时承担模型适配、流式传输、工具循环和错误处理；
- `src/server/tools.ts` 集中定义并执行所有工具，缺少统一的危险操作确认层；
- `src/lib/chatStore.ts` 同时保存会话、模型设置、API Key、同步配置和界面状态；
- `/persistent` 下的数据由多个模块分别直接读写，校验、锁和异常处理方式不一致；
- 当前只有共享登录密码，“星星”和“小火”不是服务端能够验证的两个身份；
- API Key 会进入浏览器存储和聊天设置同步；
- 自动唤醒和普通聊天共享大量具有真实副作用的工具；
- 当前自动测试和持续集成不足。

## 3. Codex 执行纪律

后续 Codex 开始任何阶段前，必须先完整阅读本文档，并遵守以下规则：

1. 一次只执行当前被用户明确批准的阶段或子任务。
2. 不得顺手开始下一块，不得把两块合在同一批修改中。
3. 开工前检查 Git 状态；保留并避开用户已有的未提交修改。
4. 每个阶段使用独立分支，默认分支名见本文档。
5. 先建立当前行为的测试，再移动或拆分实现。
6. 不直接使用线上 `/persistent` 数据做测试。
7. 不改变现有数据格式，除非该阶段明确包含迁移方案和回退测试。
8. 不在本计划中更换数据库、不重做视觉设计、不接入 Claude Code。
9. 不擅自清理 Git 历史、吊销外部 Token、部署生产环境或删除生产数据；这些动作需要用户明确授权和配合。
10. 每个阶段结束后提交一份验收报告，然后停止，等待用户确认。

每次验收报告至少包括：

- 修改了什么；
- 没有修改什么；
- 自动测试结果；
- 人工测试清单；
- 已知风险；
- 回退方法；
- 是否建议进入下一阶段。

## 4. 目标结构

第一轮拆分完成后的逻辑结构：

```text
前端界面
    ↓
轻量 API 入口
    ↓
对话与请求编排
    ├── 模型管道
    │     ├── Anthropic
    │     ├── OpenAI-compatible
    │     └── 未来预留：Claude Code 反代
    │
    └── 工具权限层
          ├── 记忆/日记/照片/待办等本地工具
          ├── 邮件/网页抓取等外部工具
          └── 数据保存层
                └── 现有 /persistent JSON 数据
```

本轮目标是“职责分开”，不是“部署分开”。所有模块可以继续在同一个 Next.js 服务中运行。只有四块全部稳定后，才评估是否需要独立后端服务。

## 7. 第二块：工具与权限层

### 分支

`codex/lumbre-02-tool-permissions`

### 目标

把工具按领域拆开，并让每次工具调用都先经过统一的权限判断。模型不能绕过权限直接执行危险操作。

### 工作范围

- [ ] 将 `src/server/tools.ts` 按领域拆分；
- [ ] 建立统一工具注册表，工具定义与执行实现分离；
- [ ] 每个工具声明操作等级和允许的调用来源；
- [ ] 建立服务端工具调用上下文，至少包含用户身份、会话、调用来源和时间；
- [ ] 工具调用来源区分普通聊天、用户确认、自动唤醒和内部任务；
- [ ] 建立统一确认流程和审计记录；
- [ ] 修复批量工具调用绕过数量限制的问题；
- [ ] 删除危险写操作的并行执行；
- [ ] 网页抓取增加协议、目标地址、重定向、大小和超时限制；
- [ ] 自动唤醒使用单独的最小工具白名单；
- [ ] 工具只能通过第一块的数据接口访问本地数据。

### 权限等级

| 等级 | 类型 | 默认行为 |
|---|---|---|
| 绿色 | 读取天气、读取记忆、读取日记等 | 可自动执行并记录 |
| 黄色 | 写记忆、写日记、修改待办等本地写入 | 允许执行并完整记录，可按工具提升为确认 |
| 红色 | 删除、发邮件、回复邮件、对外发帖、改密码等 | 必须得到当前用户确认 |
| 黑色 | 无人值守下的红色操作或未明确授权的系统操作 | 永远拒绝 |

### 建议目录

```text
src/server/agent/
├── registry.ts
├── executor.ts
├── policy.ts
├── audit.ts
├── context.ts
└── tools/
    ├── memory.ts
    ├── diary.ts
    ├── photos.ts
    ├── todo.ts
    ├── mail.ts
    ├── web.ts
    ├── wake.ts
    └── ...
```

### 测试重点

- [ ] 每个工具的注册名称、输入格式和输出格式保持兼容；
- [ ] 每个权限等级都有允许和拒绝测试；
- [ ] 自动唤醒无法执行红色工具；
- [ ] 伪造确认、重复确认和过期确认会被拒绝；
- [ ] 多个工具调用遵守统一总数限制；
- [ ] 破坏性操作按顺序执行，前一个失败时不会继续扩大影响；
- [ ] 网页抓取不能访问本机、内网、云元数据和非允许协议；
- [ ] 单个工具失败不会破坏整次聊天；
- [ ] 第一块及阶段 0 的全部测试继续通过。

### 验收门槛

- 所有工具调用都经过统一执行器和权限层；
- 红色操作无法在没有确认的情况下完成；
- 无人值守唤醒只能使用明确白名单；
- 审计记录能够回答谁在什么时候调用了什么工具以及结果；
- 预览环境连续稳定运行至少 24 小时。

### 明确不做

- 不拆模型供应商；
- 不把 API Key 迁移到新的前端设置界面；
- 不进行整体 UI 重构；
- 不接 Claude Code。

### 回退

阶段开始时保留旧工具入口的兼容包装。若新执行器出错，可切回旧入口，但红色工具的安全限制不得随回退被重新开放。

## 8. 第三块：模型调用管道

### 分支

`codex/lumbre-03-model-gateway`

### 目标

将公共聊天流程与具体模型供应商分开，统一流式事件和工具循环，并把 API Key 移出浏览器。

### 工作范围

- [ ] 从 `src/app/api/chat/route.ts` 提取公共对话编排；
- [ ] Anthropic 调用成为独立管道；
- [ ] OpenAI-compatible 调用成为独立管道；
- [ ] 统一文本、思考、工具调用、用量、完成和错误事件；
- [ ] 统一工具循环、最大调用数、重试和超时；
- [ ] API Key 仅保存在服务端；
- [ ] 浏览器只提交渠道 ID、模型 ID 和聊天参数；
- [ ] 配置同步不再包含 API Key；
- [ ] 升级时清除浏览器旧存储中的明文 API Key；
- [ ] 限制允许连接的上游地址，防止把服务端凭据发往任意地址；
- [ ] `/api/chat` 变成轻量入口；
- [ ] 为未来的 Claude Code 反代管道预留统一适配接口，但不实现接入。

### 建议接口和目录

```text
src/server/chat/
├── orchestrator.ts
├── events.ts
├── request.ts
├── errors.ts
├── credentials.ts
└── providers/
    ├── types.ts
    ├── anthropic.ts
    └── openai-compatible.ts
```

各模型管道应向上层提供等价能力，例如：

```text
发送聊天请求
返回统一事件流
列出可用模型
声明是否支持图片、工具、思考和流式输出
```

不得让前端针对不同供应商分别解析响应。

### Claude Code 预留约束

未来 Claude Code 的目标调用方式已经确定为：

```text
Claude Code `-p`
    ↓
独立反向代理
    ↓
API endpoint
    ↓
作为 Lumbre 的第三种聊天调用管道
```

它是新增调用方式，不替换 Anthropic API 或 OpenAI-compatible API。第三块只保证未来能够增加类似 `cc-proxy` 的管道；具体请求格式、会话保持、权限、部署和认证，等待用户后续提供方案后再设计。

### 测试重点

- [ ] Anthropic 普通和流式回复；
- [ ] OpenAI-compatible 普通和流式回复；
- [ ] 图片输入；
- [ ] 多轮工具调用；
- [ ] 思考内容和用量统计；
- [ ] 429 限流和自动重试；
- [ ] 上游断流、超时、无效响应和工具不兼容；
- [ ] 重 Roll 和摘要生成；
- [ ] 浏览器请求、localStorage、IndexedDB 和配置同步中不再出现 API Key；
- [ ] 阶段 0、第一块和第二块全部测试继续通过。

### 验收门槛

- 两条现有模型管道行为与拆分前一致；
- API Key 不再下发给浏览器；
- `/api/chat` 只负责鉴权、校验、调用编排层和返回结果；
- 模型供应商实现之间没有复制整套工具循环；
- 预览环境连续稳定运行至少 24 小时。

### 明确不做

- 不实际接入 Claude Code；
- 不重做聊天页面；
- 不更换聊天数据格式；
- 不迁移数据库。

### 回退

迁移期间保留旧模型入口的兼容开关。服务端凭据迁移后，即使回退，也不得重新把 API Key 同步到浏览器。

1. 确认上一个阶段已经得到用户批准；
2. 创建独立分支；
3. 检查并记录开工前 Git 状态；
4. 增加能够锁定当前行为的测试；

## 12. 红线

以下行为在整个计划中都不允许：

- 同时施工两个阶段；
- 在没有备份的情况下修改生产数据；
- 用线上 `/persistent` 直接跑测试；
- 为了测试方便而降低生产鉴权；
- 通过清空用户浏览器数据解决升级问题；
- 在拆分过程中顺便更换数据库；
- 在拆分过程中顺便重做 UI；
- 在第三块完成前接入 Claude Code；
- 把 Claude Code 进程放进当前 Next.js 进程并共享全部生产环境变量；
- 未经用户明确确认清理 Git 历史、吊销外部凭据或部署生产环境。

## 13. Claude Code 后续接入原则

Claude Code 接入是四块完成后的独立项目，不属于本计划的实施范围。

已确认的产品目标：

- 保留当前 API 调用管道；
- 通过 `-p` 运行 Claude Code；
- 使用反向代理将它包装成 API endpoint；
- 在 Lumbre 聊天中增加“走 CC 管道”的选择；
- CC 管道与普通 API 管道可以并存；
- 具体接口和部署方式等待用户后续提供。

未来设计必须满足：

- CC 运行环境与 Lumbre 的生产数据、Gmail 凭据和其他密钥隔离；
- endpoint 有独立认证、限流、超时和审计；
- 前端不直接理解 Claude Code 的专用输出格式；
- CC 输出转换为第三块定义的统一聊天事件；
- CC 的代码执行权限与 Lumbre 生活工具权限分开管理。

## 14. 完成定义

只有满足以下条件，整个分块计划才算完成：

- 四块职责边界清晰；
- 核心大文件已经按职责拆分；
- 所有数据写入经过统一数据层；
- 所有工具调用经过统一权限层；
- 模型供应商使用统一管道接口；
- API Key 不在浏览器和聊天同步中出现；
- 旧数据和旧会话能够无损升级；
- 自动测试覆盖核心流程和安全边界；
- 四个阶段均完成预览部署、人工测试和稳定观察；
- 用户确认家中的日常使用没有退化。

完成这些工作后，再单独制定 Claude Code 反代接入方案。
